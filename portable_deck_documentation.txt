==============================
VIRTUAL DECK - PROJECT GUIDE
==============================

OVERVIEW
--------
Virtual Deck is a Python/Tkinter application for handling cards in tabletop
games. It loads a deck from a JSON file, deals cards to players, and provides
basic draw, play, discard, and turn actions. It does not implement the rules of a
specific card game.

STARTING THE APP
----------------
Run the application from this folder with:

    python main.py

The main menu contains:
- Play: start a new game using the current settings.
- Resume: reopen the latest automatic checkpoint, including after leaving
  without a manual save or recovering from an application crash.
- Load: choose a saved game to resume. The file picker opens in the saves
  folder by default and can browse to another location.
- Settings: configure a new game.
- Quit: close the application.

GAME WINDOW
-----------
The game window shows the current player's hand, card counts, and a game log.
Available actions are:
- Draw Card: draw one card from the draw deck.
- Discard Selected: move the selected hand card to the discard pile.
- Play Selected Card: append the selected hand card to the end of the table.
- Play at Selected Spot: when positioned play is enabled, insert the selected
  hand card at the selected empty slot, or apply the occupied-spot setting to
  a selected table card. Empty slots appear next to table cards.
- Next Turn: pass the turn to the next player.
- Undo: when enabled in Advanced Settings, reverse the most recent action that
  changed the game state. Available undo history is preserved in saved games.
- Save: save the current game without leaving it.
- Restart Game: start a fresh game with the same players and setup. If scoring
  is enabled, choose whether to keep or reset the current scores.
- Request Point: request one point for the current player when scoring is
  enabled.
- Exit to Main Menu: ask whether to save, then return to the main menu.
- Exit to Desktop: ask whether to save, then close the application.

For either exit action, Yes saves the game, No exits without saving the current
game, and Cancel stays in the game. The window's close button behaves like
Exit to Desktop.

SETTINGS
--------
Settings are stored in configs/settings.json. The separate
configs/default_settings.json file defines the defaults. Restore Defaults in
Settings replaces the current config with those values. Current settings are
created from the defaults on first launch. They include:
- num_players: number of players (at least 1).
- cards_per_player: cards dealt to each player at the start (0 or more).
- deck_path: path to the deck JSON file. Relative paths are resolved from the
  application folder.
- save_discard_on_exit: whether to write the discard pile to
  decks/discard.json when exiting to the desktop.
- use_custom_player_names: whether custom player names are enabled.
- player_names: names used for players when custom names are enabled.
- enable_score_counter: show scores and allow players to request points.
- require_point_confirmation: require approval by all other players before a
  requested point is awarded. Each other player is asked at the start of their
  next turn, before card actions are available. A No rejects the request; Yes
  records that player's approval. When confirmation is disabled, a request
  awards the point immediately.
- allow_take_from_table: show the action for taking a selected table card into
  the current player's hand.
- allow_move_table_card_to_discard: show the action for moving a selected table
  card to the discard pile.
- allow_manual_table_cleanup: let the current player move all table cards to
  the discard pile with one action.
- clear_table_on_round_end: automatically move all table cards to the discard
  pile when the last player in turn order ends the round.
- allow_positioned_play: show empty slots above, below, left, and right of
  table cards and allow cards to be placed in those positions.
- occupied_slot_action: choose whether playing at a selected table card is
  invalid or swaps that table card with the selected hand card.
- enable_undo: show the Undo action and keep a reversible history of game
  actions. Undo history is included in saved games and the automatic checkpoint.

Both manual and automatic table cleanup move the cards into the discard pile.

The settings screen can browse for a deck file. When custom names are enabled,
one name field is shown per configured player. Every name must be non-empty.
The game checks that the deck contains enough cards to deal the requested
starting hands before it begins.

SAVED GAMES
-----------
Game saves are JSON files in the saves/ folder. Save opens a name prompt and
suggests sessionX, where X is one greater than the highest number used by an
existing sessionX.json file. Other filenames do not affect this number. The
.json extension is added automatically when omitted, and replacing an existing
save requires confirmation.

A saved game contains the deck path and remaining deck order, each player's
name and hand, the discard pile, cards played onto the table, the current
player, the original cards-per-player setting, and game history. Load
restores this state, including scores and any pending point request. Saves can
also be loaded from a JSON file outside saves/.

The app maintains a separate automatic checkpoint at saves/last_session.json.
It is refreshed when a game starts, after game actions, and when leaving the
game. Resume loads this latest checkpoint; it does not replace named saves.

DECK FILE FORMAT
----------------
Decks are JSON files with a types array and a cards array. Each card group in
cards corresponds by position to one entry in types. Example:

    {
      "types": ["Hearts", "Spades"],
      "cards": [
        ["2", "3", "A"],
        ["2", "3", "A"]
      ]
    }

This creates cards such as "2 of Hearts" and "A of Spades". The example deck
in decks/demodeck.json contains the standard 52-card deck.

PROJECT FILES
-------------
- main.py: application entry point; opens the main menu.
- mainmenu.py: main menu, settings form, game start/load, and exit handling.
- settings.py: default settings, config loading/saving, and path resolution.
- game.py: game state, dealing, drawing, discarding, and game save/load.
- deck.py: deck JSON loading, shuffling, and drawing.
- player.py: player names and hands.
- guibase.py: Tkinter game window and action controls.
- tableframe.py: displays cards played onto the shared table.
- handframe.py: displays and selects cards in the current player's hand.
- statuspanel.py: displays player, draw deck, and discard pile counts.
- cardactions.py: callbacks for draw, discard, and next-turn actions.
- configs/settings.json: current application settings.
- configs/default_settings.json: saved default settings used by Restore Defaults.
- saves/: named saves and the automatic last_session.json checkpoint.
- decks/: deck definitions and the optional discard pile output.
- backup/: older copies of application modules.

CURRENT SCOPE
-------------
The app provides a general card-handling interface rather than game rules.
Named saves are manual; Resume uses the separate automatic checkpoint.
