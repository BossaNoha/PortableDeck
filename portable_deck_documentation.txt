==============================
PORTABLE DECK - PROJECT GUIDE
==============================

OVERVIEW
--------
Portable Deck is a Python/Tkinter application for handling cards in tabletop
games. It loads a deck from a JSON file, deals cards to players, and provides
basic draw, play, discard, and turn actions. It does not implement the rules of a
specific card game.

STARTING THE APP
----------------
Run the application from this folder with:

    python main.py

The main menu contains:
- Play: start a new game using the current settings.
- Resume: reopen the latest automatic checkpoint, including after leaving
  without a manual save or recovering from an application crash.
- Load: opens the session library, showing players, next turn, and save time.
  Load, rename, or delete a named save, or use Browse to open a JSON save from
  another location.
- Settings: configure a new game.
- Quit: close the application.

GAME WINDOW
-----------
The game window shows the current player's hand, card counts, and a game log.
Available actions are:
- Draw Card: draw one card from the draw deck.
- Take from Discard: when enabled in Advanced Settings, take either the top
  discard card or choose any card from the discard pile.
- Discard Selected: move the selected hand card to the discard pile.
- Play Selected Card: append the selected hand card to the table, or to the
  current player's row when player lanes are enabled.
- Play at Selected Spot: when positioned play or player lanes are enabled,
  insert the selected hand card at the selected empty slot, or apply the
  occupied-spot setting to a selected table card. Player lanes let you target
  an empty slot in front of any player.
- Move Selected Table Card: when table-card movement is enabled, select a table
  card and an empty destination slot, then move the card there.
- Next Turn: pass the turn to the next player.
- Undo: when enabled in Advanced Settings, reverse the most recent action that
  changed the game state. Available undo history is preserved in saved games.
- Save: save the current game without leaving it.
- View Full Deck: preview every card in the original deck definition, including
  cards already dealt or drawn. Cards are grouped by symbol and sorted by value.
- Restart Game: start a fresh game with the same players and setup. If scoring
  is enabled, choose whether to keep or reset the current scores.
- Request Point: request one point for the current player when scoring is
  enabled.
- Buy Chips: when Chip Accounts are enabled, add chips to a selected player's
  account during the session.
- Play Chips: move chips from the current player's account into the shared pot.
  The amount must meet the configured minimum bet and fit the player's balance.
- Take Pot: request moving the full pot to a selected player's account. If pot
  withdrawal confirmation is enabled, every other player must approve on their
  turn; a rejection leaves the pot unchanged.
- Exit to Main Menu: ask whether to save, then return to the main menu.
- Exit to Desktop: ask whether to save, then close the application.

For either exit action, Yes saves the game, No exits without saving the current
game, and Cancel stays in the game. The window's close button behaves like
Exit to Desktop.

SETTINGS
--------
Settings are stored in configs/settings.json. The separate
configs/default_settings.json file defines the defaults. Restore Defaults in
Settings replaces the current config with those values. Current settings are
created from the defaults on first launch. They include:
- num_players: number of players (at least 1).
- cards_per_player: cards dealt to each player at the start (0 or more).
- deck_path: path to the deck JSON file. Relative paths are resolved from the
  application folder.
- save_discard_on_exit: whether the app saves the discard pile in its internal
  portable_deck/data/discard.json file when exiting to the desktop.
- use_custom_player_names: whether custom player names are enabled.
- player_names: names used for players when custom names are enabled.
- enable_score_counter: show scores and allow players to request points.
- require_point_confirmation: require approval by all other players before a
  requested point is awarded. Each other player is asked at the start of their
  next turn, before card actions are available. A No rejects the request; Yes
  records that player's approval. When confirmation is disabled, a request
  awards the point immediately.
- allow_take_from_table: show the action for taking a selected table card into
  the current player's hand.
- allow_move_table_card_to_discard: show the action for moving a selected table
  card to the discard pile.
- allow_manual_table_cleanup: let the current player move all table cards to
  the discard pile with one action.
- clear_table_on_round_end: automatically move all table cards to the discard
  pile when the last player in turn order ends the round.
- allow_positioned_play: show empty table positions and allow cards to be
  placed in them. The original horizontal row stays compact and has one
  continuation slot.
- allow_move_cards_on_table: show table positions and allow a selected table
  card to be moved to an empty position.
- allow_play_in_front_of_players: display a separate row in front of each
  player. Play Selected Card uses the current player's row; Play at Selected
  Spot can target another player's row.
- allow_draw_from_discard: add the Take from Discard action during a session.
- draw_from_discard_mode: "top" allows only the top discard; "any" opens a list
  so the current player can choose any discard card. This option applies when
  allow_draw_from_discard is enabled.
- allow_face_down_table_cards: add an action to play a card face down and an
  action to reveal an eligible face-down card on the table.
- allow_move_table_sequences: allow moving a face-up card and the cards below it
  together to another table column. This also enables positioned table play and
  table-card movement.
- allow_recycle_discard_to_deck: add an action that returns the entire discard
  pile to an empty draw deck.
- shared_discard_pile_count: number of discard piles available to every player
  (1 through 20).
- personal_discard_pile_count: number of private discard piles assigned to
  each player (0 through 20). When discarding with multiple destinations, the
  player chooses a shared pile or one of their personal piles. Drawing from
  discard can use any pile; the "any" mode lists every card in every pile.
- occupied_slot_action: choose whether playing at a selected table card is
  invalid or swaps that table card with the selected hand card.
- enable_undo: show the Undo action and keep a reversible history of game
  actions. Undo history is included in saved games and the automatic checkpoint.
- enable_chip_accounts: show each player's chip balance and the Buy Chips
  action.
- minimum_bet: minimum bet value shown as a reference when chip accounts are on.
- starting_balance: number of chips given to every player when a new game starts.
- require_pot_withdrawal_confirmation: require every other player to approve a
  request to transfer the pot. Approvals are collected at the start of each
  other player's turn. A rejection cancels the transfer.

Both manual and automatic table cleanup move the cards into the discard pile.

The settings screen can browse for a deck file. Use Check deck to validate its
JSON structure and verify the selected setup has enough cards. Decks need
non-empty type names, one list of cards per type, and at least one card. Card
values may be text or numbers. When custom names are enabled, one name field is
shown per configured player and every name must be non-empty.

Preview deck displays every card in a responsive table-style grid with up to 10
cards per row. Symbols follow their order in the deck file, and card values are
sorted within each symbol. Manage decks also includes a Preview action for each
deck in the library.

Create deck opens a deck editor. Each group has a symbol/type and a list of card
values, entered one per line or separated by commas. Duplicate a group to reuse
its cards with another symbol, then save the new JSON deck. The new deck is
selected automatically in Settings.

Manage decks lists the JSON decks in decks/ with each deck's card count and
symbols. Use selected sets it as the active deck. Edit changes the selected
deck after confirmation; Duplicate opens the editor with a copy so the original
file remains unchanged. Import validates a JSON deck before adding it to the
library. Export copies the selected deck to a chosen location.

SAVED GAMES
-----------
Game saves are JSON files in the saves/ folder. Save opens a name prompt and
suggests sessionX, where X is one greater than the highest number used by an
existing sessionX.json file. Other filenames do not affect this number. The
.json extension is added automatically when omitted, and replacing an existing
save requires confirmation.

Load opens a session library with player names, the next player, and the last
modified time. Sessions can be loaded, renamed, or deleted there. Browse opens
a JSON save from outside the saves folder.

A saved game contains the deck path, original deck definition, and remaining
deck order, each player's
name and hand, the discard pile, cards played onto the table, the current
player, the original cards-per-player setting, game history, and (when enabled)
chip account balances, the shared pot, and any pending pot-withdrawal request. Load
restores this state, including scores and any pending point request. Saves can
also be loaded from a JSON file outside saves/.

The app maintains a separate automatic checkpoint at saves/last_session.json.
It is refreshed when a game starts, after game actions, and when leaving the
game. Resume loads this latest checkpoint; it does not replace named saves.

DECK FILE FORMAT
----------------
Decks are JSON files with a types array and a cards array. Each card group in
cards corresponds by position to one entry in types. Example:

    {
      "types": ["Hearts", "Spades"],
      "cards": [
        ["2", "3", "A"],
        ["2", "3", "A"]
      ]
    }

This creates cards such as "2 of Hearts" and "A of Spades". The example deck
in decks/demodeck.json contains the standard 52-card deck.

PROJECT FILES
-------------
- main.py: application entry point; opens the main menu.
- portable_deck/app/: main menu, settings UI/configuration, and named save
  management.
- portable_deck/core/: game state, deck/player models, turn and table actions,
  scoring, undo, chip accounts, and save/load serialization.
- portable_deck/ui/: game window composition, action callbacks, and hand/table,
  status, and chip interface components.
- portable_deck/data/: internal discard-pile data maintained by the app.
- configs/: current settings and saved defaults used by Restore Defaults.
- decks/: deck definitions and the optional discard-pile output.
- saves/: named saves and the automatic last_session.json checkpoint.

CURRENT SCOPE
-------------
The app provides a general card-handling interface rather than game rules.
Named saves are manual; Resume uses the separate automatic checkpoint.
